The data flow

Four controlled hops.

op-cache is not a replacement or alias for op. It is a narrow bridge between one authenticated 1Password session and specifically scoped local commands.

01

Approve once

op signin uses the desktop integration. One Touch ID approval opens the requested profile.

02

Fetch allowlist

Only fixed op:// references in the selected profile are read. No arbitrary vault browsing.

03

Cache in Keychain

Values, account binding, references, and expiry live in macOS Keychain, encrypted at rest.

04

Inject narrowly

--only strips every other configured secret before starting the child command.

Security boundary

Convenience, with a hard edge.

The design intentionally trades repeated biometric approval for temporary, scoped local access. The scope is the allowlist, the account, the profile, and the expiry timestamp together.

What keeps the boundary honest

01
Account-bound cache

Changing from private to Everlast invalidates old entries, even when a reference name looks identical.

02
Strict parsing

A typo such as --onyl fails closed instead of silently injecting the full profile.

03
Environment scrubbing

Configured secret names inherited from the parent shell are removed before selected values are injected.

04
Automatic cleanup

Expiry rejects stale values. The watcher clears every cached profile when the Mac sleeps.

Important: during the unlock window, any process acting with your macOS user authority can execute op-cache for allowlisted secrets. Keep the list narrow and use scoped development tokens.
Cache lifecycle

Useful, then gone.

The cache is a temporary working window, not a second permanent password manager. Every path eventually returns to a locked state.

T+0

Unlock

Approve Touch ID and fetch the profile allowlist.

RUN

Work

Run many scoped commands with no additional prompt.

8H

Expire

Entries fail closed after the configured window.

ZZZ

Sleep / clear

The watcher or a manual clear removes every cached value.
